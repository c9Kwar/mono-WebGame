# 전투 접촉 피드백

기준: `10280c4`의 「이끼빛 표본화」 아트, 여성 모험가의 관절형 검 모션, 종별 공격 예고. 원화·장비·전투 수치·보상은 변경하지 않는다. `dist/contact-feedback.css`와 `game.js`의 `CONTACT_FEEDBACK`에서 접촉 형태와 시간을 조정한다.

## 전달할 정보

낡은 상아색 `#e4d5b4`, 황동 `#d8b67c`, 녹청 `#b3c8ab`, 테라코타 `#d5a393`를 사용한다. 넓은 네온광·전체 화면 플래시·카메라 흔들림은 추가하지 않는다. 기본 형태는 블러 없이 읽혀야 한다. 회복으로 오해할 수 있는 십자 대신 방패 윤곽과 확인 획으로 방어를 표시한다.

| 효과 | 확인된 발생 조건 | 핵심 형태 / 위치 | 접촉 이후 수명 |
| --- | --- | --- | --- |
| 일반 명중 | `damage()` → 기존 검의 66% 접촉 포즈 | 적 몸통의 짧은 상아색 붓획, 명중 수치 | 260ms |
| 치명타 | 치명타로 확정된 같은 접촉 이벤트 | 황동색 주 참격과 작은 교차 보조 획, `✦ 치명타` | 340ms |
| 피격 / 강타 | `monsterHit()`의 실제 피해 | 모험가 몸통을 향하는 테라코타 꺾인 획, `피격`/`강타` | 280 / 340ms |
| 방어 | 기존 방벽 판정으로 피해 감소 | 녹청 방패 윤곽과 확인 획, `⬡ 방어` 및 남은 피해 | 360ms |
| 회피 | 회피 판정, HP 차감 없음 | 접촉 폭발 없이 끊어진 바람 획, `↷ 회피 0` | 300ms |

숫자는 820ms 동안 표시한다. 기존 검 들어올리기·내려치기·복귀, 치명타 반동, 적의 종별 공격은 보존한다. 위 시간은 검의 시작이 아닌 **접촉 시점부터**다. 게임 피해·보상은 기존 함수에서 즉시 결정되며 이펙트 완료를 기다리지 않는다. 간소화·움직임 감소에서는 검 모션을 기다리지 않고 확정 결과를 바로 표시한다.

## 타이밍과 곡선

- 일반 명중: 0ms에 불투명도 .95 / 크기 .72; 42ms에 크기 1; 109ms에 불투명도 .9 / 크기 1.03; 260ms에 불투명도 0 / 크기 .96. 크기와 불투명도 구간을 구분한다.
- 치명타는 같은 구간 비율을 340ms에 적용한다. 입자는 12%까지 감추고 25%에 불투명도 .8, 이후 제한된 방향으로 감속하며 .45 크기로 소멸한다.
- 방어는 0–72ms에 가로 크기 .85→1, 72–216ms 유지, 216–360ms 소멸한다.
- 회피는 300ms 동안 오른쪽 5px에서 왼쪽 10px로 비껴가며 소멸한다. 피해 획은 생성하지 않는다.
- 숫자는 초기 위치에서 164ms에 6px 상승하고 590ms까지 읽히며, 820ms에 16px 상승·불투명도 0으로 끝난다.

모두 CSS의 밀리초 기반 애니메이션이다. 새 프레임 루프나 프레임 수 의존 분기는 없다. 장식 파편은 설정된 네 벡터 중에서 선택하며 전투용 `Math.random()`을 호출하지 않는다.

## 좌표와 우선순위

`impact-layer`의 로컬 CSS 픽셀 좌표를 사용한다. 적은 현재 `painted-enemy` 사각형의 몸통, 모험가는 기존 SVG 원화의 `(635,610)`을 `getScreenCTM()`으로 변환한다. 종별 공격이 사용하는 모험가 기준점과 같다. 카메라나 별도 월드 좌표는 도입하지 않는다. 매 접촉에서 좌표를 읽고 리사이즈 시 남은 효과를 지운다.

숫자는 작은 화면에서도 좌우 안쪽으로 제한하며 전투창 높이의 50–72%에 배치한다. `pointer-events:none`, 효과 레이어 7, 기존 HP·위험·타이머 HUD 레이어 8을 유지한다. 새 일반 접촉은 종별 스킬의 5개 버스트 예산을 소비하지 않는다.

대상별 핵심 형태는 1개만 남긴다. 방어·회피 > 치명타·강타 > 일반 명중·피격 순이며, 강한 형태는 120ms 안에 들어온 약한 후속타가 지우지 않는다. 숫자는 별도 상한 안에서 새 결과를 표시한다.

| 품질 | 대상별 숫자 | 보조 파편 | 상태 정보 |
| --- | --- | --- | --- |
| 기본 데스크톱 | 3개, 양쪽 합계 6개 | 일반 2개 / 치명타 4개 | 형태·명칭·수치 |
| 560px 이하 | 2개, 합계 4개 | 2개 | 동일 |
| 연출 간소화 / 움직임 감소 | 1개, 합계 2개 | 없음 | 작은 정적 형태·명칭·수치를 820ms 표시 |

새 접촉 그룹의 동시 DOM 상한은 데스크톱 32개, 모바일 22개, 간소화 10개다. 기존 관절 모션·스킬·배경 DOM은 이 수치에 포함하지 않는다. 풀링은 도입하지 않았다.

## 취소와 검증

그룹별 종료 타이머는 기존 `impactTimers`가 소유한다. 상한 초과 교체, 일반 종료, 일시정지, 다른 메뉴, 새로운 조우, 페이지 숨김, 리사이즈, `pagehide`에서 정리한다. 마무리 타격은 같은 조우의 전리품/승리 전환까지만 유지한다. 숨은 전투 메뉴에서는 새로운 접촉 그룹을 만들지 않는다.

- `npm test`: 전투 판정·확률·저장·보상 회귀와 신규 `contact-feedback.test.cjs`.
- `GAME_URL=http://127.0.0.1:8000 python3 tests/browser-contact-feedback.py`: 320/390/800/1440px, 시작·강조·감쇠·종료, 연속 발동 상한, 실제 타이머, 검 접촉, 취소, 간소화·움직임 감소.
- 기존 `browser-effects.py`, `browser-hero-polish.py`, `browser-field-attacks.py`, `browser-skills.py`, `browser-passive-patch.py`, `browser-art.py`: 원화·관절·스킬·후속타 호환성.

60 FPS의 16.7ms는 게임 전체 예산이다. 아래 측정은 헤드리스 Chromium의 전체 페이지 CPU 시간이며 GPU·실기기 FPS 보장이나 순수 이펙트 비용으로 해석하지 않는다.

브라우저 스킬 회귀 검사에서 이전 방벽 규칙(15% 발동·35% 감소)을 가정하던 검사를 현재 기준 커밋의 규칙(4% 발동·30% 감소)에 맞췄다. 수정 전 기준 커밋과 작업 버전에서 같은 실패를 재현했으며, 게임의 방벽 수치는 변경하지 않았다.

최종 검증: 단위 테스트 147개 및 기존 자산·이미지·밸런스 검사 통과. 신규 접촉 검수와 기존 효과·모험가 관절·일반 종별 공격·스킬·패시브·원화 브라우저 검사 7종 통과. 다른 메뉴에서 돌아온 첫 타격의 접촉 예약도 회귀 검사에 포함한다. 브라우저 검수는 실제 Chromium이며 모바일 항목은 뷰포트/터치 에뮬레이션이다.

## 측정 기록

동일한 6초 시퀀스(공격 18회, 그중 치명타 4회 / 피격 5회, 그중 방어 2회)를 화면 크기별 2회 실행한 중앙값이다. Chromium 헤드리스, DPR 1, 모바일은 터치/뷰포트 에뮬레이션. 게임의 100ms 갱신은 실행하고 자동 공격 시계만 멀리 둬 두 버전에 같은 사건을 입력했다. 원화와 서버 조건은 같으며 스크린샷은 측정 구간 밖에서 촬영했다.

CPU 열은 **6초 전체 페이지 누적 ms**, 마지막 열은 rAF 간격의 95백분위 ms다. Task는 아래 하위 항목을 포함하므로 합산하지 않는다.

| 화면 | 버전 | Script | Layout | Style | 전체 Task | rAF p95 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 데스크톱 1440×1000 | 기준 | 95.43 | 117.94 | 193.09 | 1076.73 | 16.80 |
| 데스크톱 1440×1000 | 접촉 개선 | 107.70 | 116.28 | 141.32 | 841.08 | 16.75 |
| 모바일 390×844 | 기준 | 101.31 | 100.91 | 187.72 | 909.22 | 16.80 |
| 모바일 390×844 | 접촉 개선 | 96.47 | 99.83 | 134.78 | 772.30 | 16.80 |

이 표는 제한된 표본의 관찰값이다. 모바일 실기기·GPU 래스터·전체 드로우 콜을 측정하지 않았으며 60 FPS를 보장하지 않는다. 효과 그룹/타이머 상한은 별도 회귀 검사로 검증했다.
