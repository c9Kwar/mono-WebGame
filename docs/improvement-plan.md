# 모스라이트 자율 개선 계획 · 2026-10-11

## 구조 분석

빌드 없는 정적 웹 게임. `dist/index.html`에 8개 작업 화면·다수 상세 모달, `dist/style.css`에 반응형 레이아웃·전투 연출, `dist/game.js`에 전투·경제·저장·DOM 렌더링이 함께 있다. 이미지 29개는 실행용 WebP이며 원본 제작 기록은 `art-notes.md`에 있다. 실행 문서는 README, 과거 콘텐츠와 검증은 release-notes에 기록되어 있다.

주요 시스템: 실시간 자동 전투, 지역 이동·회복·사망 후퇴, 반복 사냥, 6종 능력 강화, 장비 5부위·개별 옵션·잠재 재설정·분해, 18종 제작법, 일반/특수 패시브, 5보스·3변이, 11몬스터, 60아이템, 12수집 세트, 단계 보상, 조사 의뢰, 자동 탐사와 유물, 발견 기록·제작 목표. 저장은 `mosslight.save.v1`; 오프라인 보상은 골드만, 8시간·추정 온라인 효율 50%. 이전 전투 원정 함수 3개는 호환용 비활성 스텁이며 미완성 콘텐츠로 오인해 다시 켜면 안 된다.

기존 테스트: 콘텐츠/저장·자산/화면·이미지 비동기·대표 성장의 보스 전투·패시브 예산 5개 스크립트. 신규 실브라우저 QA와 CI가 필요하다. 서버 계정·클라우드 저장·랭킹은 없고 GitHub 변경이 운영 Sites를 자동 배포하지 않는다.

## 이번 묶음의 완료 기준과 다음 작업

17개 과제 완료, CI 구성 1개(원격 실행 미확인), 부분 구현 3개, 경제/수치 분석 후 조정 보류 2개, 다음 작업 5개. 저장 교체에는 플레이어 확인과 원본 백업 성공이 필수이며, 자동 데이터 초기화는 없다. 탭 충돌 감지는 저장 스냅샷 비교와 storage 이벤트 방식이며 분산 트랜잭션/기기 간 동기화는 아니다.

다음 순서는 장비 목록 페이지화(#20)로 큰 가방 렌더 병목을 측정하고, 보스/사냥/수급 추천 프리셋(#19)을 만든 뒤 최상위 패시브의 기대 획득 비용(#22)을 조정하는 것이다. 첫 신화 패시브의 기본 기대 500회 뽑기와 Lv.5 기대 약 5708회를 그대로 유지했으므로 이를 이번 작업의 해결 항목으로 표시하지 않는다. 자료와 재현 명령은 balance-review.md, validation-report.md를 참고한다.
