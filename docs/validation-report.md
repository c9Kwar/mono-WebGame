# 검증 기록 · 2026-10-11

## 실행 환경과 범위

Node.js 24, Python 3, Playwright 1.62.0 및 실제 Chromium을 사용했다. `npm test`는 구문 검사, 43개 Node 회귀 테스트, 기존 5개 자산·콘텐츠·밸런스 스크립트를 실행한다. `npm run test:browser`는 실행 중인 정적 서버를 대상으로 한다. CI 구성은 추가했으며 원격 Actions 실행 결과는 별도 확인이 필요하다.

## 회귀 검사

- 잘못된/미래 저장 원본 보존, 쓰기 불가·용량 부족, 교체 전 백업, legacy 배열 확장, 동시 탭 충돌, 장비 개체 속성과 잠금 저장.
- 전투 타이머 복구, 오프라인 보상 제외 상태, 잘못된 시간·피해 입력, 주입 난수에 따른 방벽, 오래된 보스 해금 보존.
- 설계도 자연 획득·60회 보장·변이·소유 중복 처리, 연속 사망 보호와 해제, 일반 보스 선택, 제작 목표 소모 없는 미리보기.
- 10,000 구간 확률 열거, 전투 상한, 기존 자산·콘텐츠·대표 성장 프로필.

## 실제 브라우저에서 통과한 항목

8개 탭 이동, 새로고침과 내보내기, 두 탭 충돌 후 자원 변경 차단, 잘못된 가져오기와 취소 시 원본 보존, 확인 후 legacy 가져오기와 원본 백업을 확인했다. 제작 목표 수급처, 실제 제작과 장비 잠금·분해 차단을 확인했다. 390/800/1440px 화면에서 실제 장비와 펼친 제작 목표에 가로 넘침이 없었다.

일반 보스전을 실제 시간으로 완료해 승리와 설계도 보장을 확인했다. 결과 창을 닫고 새로고침·재열기해 보상 중복 지급이 없음을 확인했다. 손상 저장의 정확한 원본 내보내기와 저장 접근 금지 상태의 임시 플레이를 검사했다. JavaScript 오류와 HTTP 오류는 발생하지 않았다.

## 호환성 및 제한

저장 키 `mosslight.save.v1`과 기존 버전을 유지한다. 저장 검증의 안전 범위는 10MB, 깊이 25, 스테이지 0~1000, 장비 20,000개다. 범위를 넘는 기존 저장은 보호 상태로 보존하며 자동 초기화하지 않는다. 가져오기는 확인과 원본 백업 성공 후 적용하고 시간을 현재로 재설정한 일시정지 상태로 연다. 최근 교체 전 백업 하나만 보관한다.

탭 충돌 감지는 스냅샷 비교와 storage 이벤트 기반으로 원자적 분산 잠금이 아니다. 한 탭 사용을 권장한다. 주소별 저장은 별개이며 클라우드 동기화는 추가하지 않았다. 운영 사이트 배포나 운영 저장 삭제는 수행하지 않았다. 신규 몬스터·주간 콘텐츠·큰 가방 페이지화·추천 장비 프리셋은 후속 과제다.
