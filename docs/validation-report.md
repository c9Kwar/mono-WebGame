# 검증 기록 · 2026-10-11

## 실행 환경과 범위

Node.js 24, Python 3, Playwright 1.62.0 및 실제 Chromium을 사용했다. `npm test`는 구문 검사, 43개 Node 회귀 테스트, 기존 5개 자산·콘텐츠·밸런스 스크립트를 실행한다. `npm run test:browser`는 실행 중인 정적 서버를 대상으로 한다. CI 구성은 추가했으며 원격 Actions 실행 결과는 별도 확인이 필요하다.

## 회귀 검사

- 잘못된/미래 저장 원본 보존, 쓰기 불가·용량 부족, 교체 전 백업, legacy 배열 확장, 동시 탭 충돌, 장비 개체 속성과 잠금 저장.
- 전투 타이머 복구, 오프라인 보상 제외 상태, 잘못된 시간·피해 입력, 주입 난수에 따른 방벽, 오래된 보스 해금 보존.
- 설계도 자연 획득·60회 보장·변이·소유 중복 처리, 연속 사망 보호와 해제, 일반 보스 선택, 제작 목표 소모 없는 미리보기.
- 10,000 구간 확률 열거, 전투 상한, 기존 자산·콘텐츠·대표 성장 프로필.

## 실제 브라우저에서 통과한 항목

8개 탭 이동, 새로고침과 내보내기, 두 탭 충돌 후 자원 변경 차단, 잘못된 가져오기와 취소 시 원본 보존, 확인 후 legacy 가져오기와 원본 백업을 확인했다. 제작 목표 수급처, 실제 제작과 장비 잠금·분해 차단을 확인했다. 390/800/1440px 화면에서 실제 장비와 펼친 제작 목표에 가로 넘침이 없었다.

일반 보스전을 실제 시간으로 완료해 승리와 설계도 보장을 확인했다. 결과 창을 닫고 새로고침·재열기해 보상 중복 지급이 없음을 확인했다. 손상 저장의 정확한 원본 내보내기와 저장 접근 금지 상태의 임시 플레이를 검사했다. JavaScript 오류와 HTTP 오류는 발생하지 않았다.

## 호환성 및 제한

저장 키 `mosslight.save.v1`과 기존 버전을 유지한다. 저장 검증의 안전 범위는 10MB, 깊이 25, 스테이지 0~1000, 장비 20,000개다. 범위를 넘는 기존 저장은 보호 상태로 보존하며 자동 초기화하지 않는다. 가져오기는 확인과 원본 백업 성공 후 적용하고 시간을 현재로 재설정한 일시정지 상태로 연다. 최근 교체 전 백업 하나만 보관한다.

탭 충돌 감지는 스냅샷 비교와 storage 이벤트 기반으로 원자적 분산 잠금이 아니다. 한 탭 사용을 권장한다. 주소별 저장은 별개이며 클라우드 동기화는 추가하지 않았다. 운영 사이트 배포나 운영 저장 삭제는 수행하지 않았다. 신규 몬스터·주간 콘텐츠·큰 가방 페이지화·추천 장비 프리셋은 후속 과제다.

## 후속 묶음: 원정 준비실

`npm test`는 49개 회귀 테스트와 기존 5개 검사를 통과했다. 신규 검사는 목적 저장과 무소모 미리보기, 목적별 다른 추천, 동점일 때 현재 장비 유지, 1,000개 장비의 페이지 상한, 목적별 분해 보호를 포함한다.

`python3 tests/browser-preparation.py`에서 목적 선택·명시적 장착·재접속·키보드 조작·390/800/1440px 레이아웃 및 1,006개 장비 페이지 전환을 검사한다. 최초 측정에서 24행 목록 렌더 호출은 Chromium에서 6.9ms였다. 단일 환경의 호출 시간이며 저사양 기기의 전체 프레임 시간이나 20,000개 저장을 보장하지 않는다. 전체 배열 정렬·서명 계산은 여전히 목록 길이에 비례한다.

보스·사냥·수집 가중치는 추천만 바꾼다. 실제 스탯·드롭·재화 생성 규칙은 변경하지 않았다. 기존 실제 브라우저 저장·보스전 회귀 검사도 함께 유지한다. 브라우저 검사는 `npm run test:browser`로 두 스크립트를 순서대로 실행한다.

## 보스 준비 점검 추가 검증

전체 회귀 테스트는 53개다. 읽기 전용 계산, 생존/시간 부족 구분, 잘못된 입력 방어, 현재 체력에 따른 화면 갱신을 추가 검사했다. 고정 난수와 무발동 조건의 4개 프로필에서 실제 승패·처치/사망 시간이 예측과 0.1초 이내로 일치하며, 승리 시 남은 체력도 일치했다. 실제 브라우저 검사는 준비/생존 부족 표시, 저체력 회복 안내, 공략 장비 바로가기와 3개 화면 폭의 모달 넘침을 추가 확인한다. 전체 무작위 빌드의 승리 가능성을 보장하는 검사는 아니다.

## 전투 연출 묶음

회귀 테스트 56개와 기존 5개 검사 통과. 추가 검사는 이펙트의 게임 상태/난수 무변경, 100회 연속 발생에도 최대 5묶음·35개 자식 유지, 조우 전환 정리, 간소화/일시정지/숨김/모션 감소 시 발생 억제를 확인한다.

실제 Chromium의 `tests/browser-effects.py`는 효과 발생과 CSS 애니메이션 연결, 자동 제거, 390/800/1440px 가로 넘침, 연출 설정 재접속 유지, 실행 중 OS 모션 감소 전환과 화면 진동 비활성화를 검사한다. 저장·실시간 보스전 브라우저 회귀 검사도 통과했다. 대표 전투/패시브 시뮬레이션 결과는 기존과 동일하다. 저사양 실기기의 FPS나 GPU 사용량은 별도 측정이 필요하며, 이번 검사는 프레임 속도 보장을 뜻하지 않는다.

## 내려치기와 보스·엘리트·황금여우 스킬

PR #1의 최신 커밋 `9b8e0cf`를 기준으로 `improve/mosslight-save-and-growth`에서 작업했다. 시작 시 미커밋 변경은 없었으며, 기존 저장 모듈과 WebP 원본을 그대로 유지했다.

Node.js 24.19, Python Playwright 1.62.0, Chromium 154에서 `npm test`와 `npm run test:browser`를 실행했다. Node 회귀 파일 10개(테스트 65개)와 기존 콘텐츠·자산·이미지·밸런스 검사 5개, 실제 브라우저 검사 4종이 통과했다.

- SVG의 실제 화면 좌표로 준비·머리 위 유지·내려치기·복귀를 검사했다. 390/800/1440px, 일반·치명타·동시 피격을 포함한다. 일반 공격에서 검끝이 준비 자세보다 약 31~59px 올라가며 머리 위를 통과하고, 아래로 약 98~189px 이동했다.
- 초당 3회 공격과 마지막 일격에서도 동작이 완료되는지 확인했다. 100ms 동안 메인 스레드를 막아 렌더링을 지연시켜도 실제 CSS 동작 진행률에 맞춰 타격하고 복귀가 끝난 뒤 정리된다. 처치 보상은 기존 전투 시점에 한 번 지급한다.
- 일반·엘리트 전체 11종의 독립된 캐릭터 레이어, 보스 5종·엘리트 5종의 이름·예고·피해·실제 CSS 효과를 확인했다. 왕관·달빛·포자·여우의 계산된 색과 효과의 가시성을 검사했다.
- 황금여우의 등장·공격·승리 효과가 반복 렌더에서 중복 발생하지 않으며, 승리 후 재접속·보상 다시 보기에서도 골드·아이템·장비가 중복 지급되지 않음을 확인했다.
- 효과 100회 발생 시 최대 5묶음, 피해 숫자 최대 10개와 해당 정리 타이머 상한을 확인했다. 조우 전환·일시정지·탭 숨김·실행 중 모션 감소 전환 때 취소되며 간소화에서도 스킬 텍스트가 남는다.
- 기존 저장 내보내기·가져오기·백업·탭 충돌·장비 잠금·준비실·실시간 보스 승리 검사도 통과했다. JavaScript·HTTP 오류와 세 화면 폭의 가로 넘침은 없었다.

보스 피해량·주기·설계도·드롭 수치는 변경하지 않았다. 표시용 피해 숫자 위치에서 게임 난수 사용을 제거했으므로 같은 seed의 개별 발동 순서는 이전과 달라질 수 있다. 40개 seed의 패시브 예산 검사에서 무패시브 평균 32.98초, 일반 풀 최대 레벨 평균 19.80초였고 기존 예산 검사를 통과했다. 실제 플레이어의 재미·저사양 기기 FPS·다른 브라우저 엔진은 이번 검증 범위에 포함하지 않는다.

## 이끼빛 표본화 · 아트 통합

PR #1과 원격 브랜치의 `ae1efa5`가 일치하는 것을 확인하고 후속 작업했다. 기존 커밋·저장 모듈·WebP 원본을 보존했다. 새 원화는 `dist/art/`의 PNG 4개이며 생성본을 그대로 복사하고 브라우저의 표시 영역과 SVG 관절로 배치한다.

- `npm test`: 회귀 파일 11개와 기존 콘텐츠·자산·이미지·밸런스 검사 5개 통과. 생물 16종과 장비 27종의 독립 원화, 전체 아이템 60종의 연결, 이미지 실패 시 대체 아이콘, 그림 교체의 저장·게임 난수 무변경을 확인했다.
- 실제 Chromium의 기존 네 브라우저 검사 통과: 저장 내보내기/가져오기/백업/탭 충돌, 준비실·장비 잠금·실시간 보스 승리·보상 재접속, 스킬과 공격 모션의 수명·모션 감소·간소화·마지막 일격을 보존했다.
- `tests/browser-art.py`: 16종의 전투·도감 그림, 보스 5종의 원정·빠른 원정 초상, 실제 장비 페이지의 27종, 가방 아이템 60종과 제작법 18개를 확인했다. 실제 표시 너비·높이와 이미지의 가로·세로 확대율로 비율 왜곡을 검사했다.
- 8개 탭을 390/800/1440px에서 검사했다. 가로 넘침, JavaScript 오류, 정상 로딩의 HTTP 오류가 없었다. 실제 원화 목록과 인물의 준비·머리 위·내려치기 자세를 화면으로 확인했다.
- 새 원화 요청을 모두 실패시키는 검사에서 중립 배경과 재시도 안내를 확인했다. 구형 기사가 포함된 배경이나 불필요한 이전 WebP 요청이 발생하지 않는다. 기존 완성 장면은 다음 장면의 이미지가 모두 해독될 때까지 유지된다.

이번 변경은 표현 계층에 한정하며 기본 전투·드롭·비용·저장 규칙은 유지한다. 원본 PNG 4개는 합계 약 11MB이며 같은 시트를 캐시해 재사용한다. 손실 압축 최적화, 저사양 기기 FPS와 Chromium 외 브라우저 검증은 이번 범위에 포함하지 않는다. 운영 배포는 수행하지 않았다.

## 보스 성장 업데이트

보스 관통·재생, T1~T8 장비와 보스별 확정 전리품의 최신 규칙·회귀 및 실제 브라우저 검증은 [보스 성장 검증](boss-growth.md)에 기록했다. 위 이전 단계의 배포 전 기록과 구분한다. 현재 자동 검사 구성은 Node 회귀 파일 12개와 기타 검사 5개, 실제 Chromium 검사 6종이다.

## UI 밀도·분해 수정 · 2026-10-11

- 보스 전체 설명 카드를 작은 선택 행으로 교체. 클릭하면 기존 원정 상세창에서 준비도와 입장 버튼을 확인하고, 스킬·전리품·기록은 접었다 펼친다. 모바일 목록은 가로 스크롤을 지원하며 선택한 보스로 이동한다. 재도전 타이머 갱신 시 선택 행 DOM을 보존한다.
- 장비 준비 그림과 추천 비교를 기본 접힘으로 변경. 전체 장비는 모바일 2열, 작은 그림·한 줄 동작 버튼으로 표시한다. 전투 장면 크기는 유지한다. 상세 정보는 클릭·터치·키보드로 접근 가능하다.
- 교체 후보가 없어도 추천 버튼을 활성화하고, 다시 누르면 비교 내용을 펼친다. 장비를 얻지 않은 경우에도 적절한 안내를 표시한다.
- 희귀 이하 일괄 분해에서는 추천·대성공·가호를 더 이상 자동 제외하지 않는다. 잠금·장착은 계속 보호하며, 영웅의 추천·특수 옵션 보호와 전설/신화 개별 분해 규칙도 유지한다. 장비 목록과 분해 확인창에 규칙을 표시한다. 개별 분해 버튼에는 잠금/장착 중인 이유를 표시한다.
- `npm test` 회귀 파일 13개 및 기존 별도 검사 통과. Chromium 7종을 실행해 저장·전투·준비·연출·아트·티어·컴팩트 UI를 검증했다. 공격 애니메이션 종료 타이밍 검사 1회 실패는 해당 스크립트를 단독 재실행해 통과했다. 390/800/1440px에서 보스 5행 총 높이 560px 미만, 장비 카드 115px 미만, 모바일 2열과 가로 넘침 없음, 실제 희귀 분해/보호/재접속, 추천 비교 버튼을 확인했다. 모바일 보스 목록·상세·장비 스크린샷을 직접 검토했다.
